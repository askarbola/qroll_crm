Add testTelegramConnection method to ConfigurationController using Guzzle HTTP client following WebhookService pattern (research lines 109-144).

Method signature:
```php
public function testTelegramConnection(Request $request): JsonResponse
```

Implementation:
1. Validate inputs: bot_token (required|string), chat_id (required|integer)
2. Create Guzzle client with timeout=10, connect_timeout=5, http_errors=false
3. Step 1 - Test bot token: GET https://api.telegram.org/bot{$botToken}/getMe
   - Check $response->getStatusCode() === 200 && $body['ok'] === true
   - Extract bot name from $body['result']['first_name']
   - Return 400 error if invalid token
4. Step 2 - Test message send: POST https://api.telegram.org/bot{$botToken}/sendMessage
   - JSON payload: { chat_id: (int)$chatId, text: "Test message from Krayin CRM", parse_mode: "HTML" }
   - Check response ok === true
   - Return 400 error if failed (common: "chat not found" for wrong chat_id)
5. Wrap both steps in try-catch for RequestException
6. Return JsonResponse with success boolean and message string

Add route to configuration-routes.php:
```php
Route::post('telegram/test', [ConfigurationController::class, 'testTelegramConnection'])->name('admin.configuration.telegram.test');
```

Use existing middleware stack (web, admin_locale, user) from route group.

CRITICAL: Cast chat_id to integer for Telegram API (handles negative group IDs correctly per research pitfall #2). Always catch RequestException and check $e->hasResponse() before accessing response (research pitfall #3).
