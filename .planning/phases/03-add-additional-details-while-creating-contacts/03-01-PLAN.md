  <action>
Create a Laravel migration in `database/migrations/` (NOT in the Webkul Installer package -- this is a project-level customization).

The migration must:

1. Get the current max sort_order for persons attributes: `DB::table('attributes')->where('entity_type', 'persons')->max('sort_order') ?? 6`

2. Insert 9 attributes using idempotent checks (check existence before insert). Use `$now = Carbon::now()` for timestamps. All attributes use `entity_type => 'persons'`, `is_user_defined => '1'`, `quick_add => '0'`.

Attributes to insert (in this sort_order sequence):

| # | code | name | type | is_required | sort_order |
|---|------|------|------|-------------|------------|
| 1 | contact_type | Contact Type | select | 0 | $maxSortOrder + 1 |
| 2 | ssn | SSN | text | 0 | $maxSortOrder + 2 |
| 3 | date_of_birth | Date of Birth | date | 0 | $maxSortOrder + 3 |
| 4 | filing_status | Filing Status | select | 0 | $maxSortOrder + 4 |
| 5 | occupation | Occupation | text | 0 | $maxSortOrder + 5 |
| 6 | business_name | Business Name | text | 0 | $maxSortOrder + 6 |
| 7 | ein | EIN | text | 0 | $maxSortOrder + 7 |
| 8 | entity_type_tax | Entity Type | select | 0 | $maxSortOrder + 8 |
| 9 | fiscal_year_end | Fiscal Year End | text | 0 | $maxSortOrder + 9 |

IMPORTANT: Use `entity_type_tax` as the code for "Entity Type" (not `entity_type`) because `entity_type` is already a column in the attributes table itself and would cause conflicts.

3. For each select attribute, use `insertGetId` to get the attribute ID, then insert options into `attribute_options`:

**contact_type options:**
- Individual (sort_order 1)
- Business (sort_order 2)

**filing_status options:**
- Single (sort_order 1)
- Married Filing Jointly (sort_order 2)
- Married Filing Separately (sort_order 3)
- Head of Household (sort_order 4)
- Qualifying Widow(er) (sort_order 5)

**entity_type_tax options:**
- LLC (sort_order 1)
- S-Corp (sort_order 2)
- C-Corp (sort_order 3)
- Partnership (sort_order 4)
- Sole Proprietorship (sort_order 5)
- Non-Profit (sort_order 6)

4. The `down()` method must:
- Delete attribute_options for these attributes (cascade handles this via FK, but be explicit)
- Delete the 9 attributes from the attributes table by code + entity_type

5. Follow the exact coding conventions from the existing migration pattern (anonymous class, Carbon for timestamps, aligned => operators).

6. Set `lookup_type => null` and `validation => null` for all attributes. Set `is_unique => '0'` for all.

  <action>
Modify TWO Blade files to add `data-attribute-code` attributes on wrapper divs. This is needed so JavaScript can target specific attribute fields for conditional visibility (Plan 02).

**File 1: `packages/Webkul/Admin/src/Resources/views/components/attributes/index.blade.php`**

The current `<x-admin::form.control-group>` line is:
```blade
<x-admin::form.control-group class="mb-2.5 w-full">
```

Change it to:
```blade
<x-admin::form.control-group class="mb-2.5 w-full" data-attribute-code="{{ $attribute->code }}">
```

The `form.control-group` component uses `$attributes->merge(...)` which passes through any extra HTML attributes, so `data-attribute-code` will render on the wrapper div.

**File 2: `packages/Webkul/Admin/src/Resources/views/components/attributes/view.blade.php`**

The current wrapper div for each attribute is:
```blade
<div class="grid grid-cols-[1fr_2fr] items-center gap-1">
```

Change it to:
```blade
<div class="grid grid-cols-[1fr_2fr] items-center gap-1" data-attribute-code="{{ $attribute->code }}">
```

Do NOT change any other lines in either file. These are minimal, surgical changes.
  </action>

  </verify>
